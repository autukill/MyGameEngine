## 任务：推演 GameInstance 事件模型 + Pass/shader 管理与装配（尚未实施，plan 阶段）

用户明确方向：VisualTests 的业务逻辑不应堆在 Program.cs 静态方法里，应像 GameMaker 一样放入 GameInstance，通过事件（Create/BeginStep/Step/EndStep/Draw...）控制业务逻辑与 shader/blend mode。

### 现状诊断
- EngineWindow 主循环管道已具备：PreStep→Step→PostStep→DrawBegin→Draw→DrawGUI。
- GameInstance 仅 4 事件：OnCreate/OnStep/OnDraw/OnDestroy —— 缺 Begin/End Step、Begin/End Draw、DrawGUI、输入事件。
- SceneAggregate：Layer + PerformStep(OnBeforeStep→OnStep→OnAfterStep) + DrawActive(按 Layer+Depth 调 OnDraw)。
- SpriteBatch 自动 Flush 只有"纹理切换/缓冲满"，无 Blend 状态打断。
- BlendState 在 RenderPipeline.Domain，依赖 Silk.NET.OpenGL（BlendingFactor）→ 不能提升到 Core。
- LayerRenderState（Layer 级 Shader/Blend/Stencil 覆盖）已存在。
- RequestStencilMask 是"实例→领域事件→Pass 装配"的既有范式。
- SpriteRef 是"资源引用值对象"既有范式。

### 推演结论（用户已认可方向）
三层职责模型：
1. 拓扑层：Pass 图由组合根（Program/ScenePipelineBuilder）显式装配。
2. 状态层：实例用 RenderStyle 值对象（BlendMode/Depth）+ OnDraw 内 batch.SetBlendMode 声明渲染状态。
3. 特需层：实例发 RenderEffectRequested 事件，PipelineBuilder 消费装配特需 Pass（泛化 RequestStencilMask）。

关键设计：
- Shader 用 ShaderRef(string Name) 值对象 + ShaderLibrary（Infrastructure）解析，实例不持 GL 对象（保 VSA 依赖方向）。
- RenderStyle 状态机：SceneRenderPass 遍历实例时 diff→Flush→Apply→复位 Default，杜绝 blend 泄漏。
- BlendMode 枚举放 Core（无 Silk）；ISpriteBatch 加 SetBlendMode（变更即 Flush）。
- 输入：IInputProvider 接口（Core，无 Silk）+ EngineWindow 缓存设备（复用 08-06 修复经验）+ OnKeyDown/OnKeyUp 沿事件。
- 相机用 CameraRig : GameInstance 表达（OnStep 控相机），矩阵应用仍在 Pass。

### 深入推演补充（2026-08-07 同日）
"如何新增 shader/pass"推演结论：
- **扩展点现状**：RenderPipeline 已自动拓扑排序（按 Output/Inputs）；PostProcessPass 是通用后处理入口（输入RT+IShader→输出RT）；IShader 接口统一；缺 ShaderProgram 统一基座、缺 ShaderLibrary、缺统一 uniform API。
- **新增 shader 最佳实践**：ShaderProgram 基座（通用编译+uniform location 字典缓存，miss 才 GetUniformLocation）+ ShaderLibrary 注册；GLSL 主路径 const string 集中管理（AI 切片友好）；实例只持 ShaderRef(name)。两种 uniform：静态参数进 ShaderRef 参数表（声明式），动态参数用 batch.SetShaderUniform（命令式）。
- **新增 pass 最佳实践**：五步模板（继承+Output/Inputs+ctor 注入 GL/shader/RT/参数+Execute）；三种装配模式：静态（组合根 AddPass/builder 扩展）、实例事件（RenderEffectRequested→Pass 工厂，泛化 RequestStencilMask）、动态开关（IsEnabled/RemovePass）。EffectDescriptor（Domain 值对象）只声明效果，Pass 工厂（Infrastructure）决定实现。
- **深水区关键结论**：
  1. GL 状态机归 SpriteBatch（唯一入口防失同步；变更即 Flush 与纹理打断同构）。
  2. 实例状态机复位点在 Pass.End() 而非每实例（Begin 记录快照/End 统一复位，同状态连续实例零切换）。
  3. ShaderRef 引用判等陷阱：OnCreate 创建一次存字段、原地改参数数组；名称用编译期常量 → RenderStyle 判等退化为值+引用对比，零分配。
  4. ShaderProgram uniform location 用 Dictionary 缓存（仅 miss 调 GetUniformLocation）。
  5. 动态 Pass 装配生命周期：RT 用 RenderTargetPool；ShaderLibrary 窗口级生命周期；kind 聚合 HashSet<InstanceId> owners，空集才移除 Pass；OnAfterStep 消费事件仅 diff 时重建。
- **分两阶段落地**：阶段1=静态装配+实例 RenderStyle 状态机+VisualTests 重构；阶段2=RenderEffectRequested 事件装配+RT 池+回收（不阻塞主目标）。
