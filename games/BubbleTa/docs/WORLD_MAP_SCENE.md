# BubbleTa.WorldMapScene 考古与渐进重建规格

> 状态：旧 `rm_world` 已完成第一轮只读考古；正式世界地图美术、关卡节点和运营入口尚未迁入。

## 旧 Room 的真实结构

旧 `rm_world` 不是一张背景长图，也不是 100 个独立 Room。它是一个 `1048×16100`、46 FPS 的容器，只预放置一个 `obj_world_control`。活动 View 为 `720×1280`，初始 `xview=180`。

`obj_world_control` 在 Create 事件中动态建立五个岛屿段：

| 组 ID | 起始 Y | 主题资源 | 关卡范围 | 方向 |
|---:|---:|---|---:|---:|
| 4 | 550 | `island_0` 复用 | 81–100 | -1 |
| 3 | 3550 | `island_3` 雪原/城堡 | 61–80 | +1 |
| 2 | 6800 | `island_2` 沙漠/绿洲 | 41–60 | -1 |
| 1 | 10050 | `island_1` 草原/风车 | 21–40 | +1 |
| 0 | 13300 | `island_0` 森林/村落 | 1–20 | 底部固定段 |

每段有 20 个手工坐标关卡点。节点精灵区分普通、计时和移动目标；锁定状态另用 `spr_levelSpot_lock`。岛屿本体由上下两张约 `455–530 × 668–688` 的图片以 2 倍缩放绘制，所以单段视觉高度约 2700px，而不是一张超大纹理。

## 相机与输入

旧控制器实现的是移动端触摸地图手感：

- 顶部 120px 被视为固定信息区，不参与地图点击。
- 按下后记录 GUI 相对坐标；拖动量经约 0.3 的追随系数逐步消费。
- 主要方向由横纵位移绝对值决定；纵向是默认方向，横向只在全局允许时启用。
- 释放距离超过 80px 且按压时间短于约 300ms 时追加一次 80px 的惯性脉冲。
- 纵向软边界位于顶部 200px 和底部 `roomHeight - viewHeight - 200`；越界后使用衰减与回弹恢复。
- 横向正常范围约为旧 View 的 `x=180..148` 所定义中心区，额外允许半边界橡皮筋；它服务于岛屿横向漂移，而不是自由横向探索。

关卡定位根据 `global.level_move` 找到节点并把相机 Y 居中。每个 20 关分段的前 3 关额外上移约 300px，后 3 关额外下移约 250px，以避免节点靠近屏幕边缘。

## 可见性与景观效果

旧实现已经包含一种手工流式策略：

- 仅相交当前 View 的岛屿段设为 visible。
- 不可见段的 20 个关卡入口和装饰实例被 deactivate。
- 风车、青蛙、人物、苹果、烟、灯光、雪和粒子等装饰按岛屿主题创建。
- 相机进入岛屿下部时，开放岛屿会横向与纵向漂移，关卡点和部分装饰跟随。
- 相邻岛屿之间插入上下云层，并依据滚动进度混合天空颜色。
- 未解锁岛屿使用遮罩云层和拨云交互，而不是简单降低透明度。

这些行为应被理解为“分段景观、相机反馈、可见性管理”三个职责，不应重新集中到一个上帝控制器中。

## 产品与运营耦合

旧 World Room 同时创建体力/货币信息、设置、商店、奖励、每日任务、签到和抽奖入口。点击关卡还会打开开始面板，并参与新关解锁动画、引导、统计 SDK 和付费流程。

现代重建明确拆开：

- 景观层：岛屿段、云层、天空颜色和装饰。
- 导航层：相机拖动、边界、定位和可见性。
- 进度层：Locked、Available、Completed 和当前关。
- 产品层：关卡详情、资源栏和其他入口。

当前阶段只推进前三层的稳定数据边界，不复刻商店、签到、抽奖、支付、广告或第三方统计。

## MyGameEngine 映射

建议的数据与实例结构：

```text
WorldMapScene
├── WorldMapCameraController       # 拖动、惯性、软边界和定位
├── WorldMapSegment[5]             # 主题、范围、天空色和包引用
│   ├── Island artwork
│   ├── Scenic decorations
│   └── LevelNode[20]
└── WorldMapProgressSnapshot       # 纯数据，不直接访问存档后端
```

Scene 使用独立 `bubbleta.world-map` 包；Home 使用 `bubbleta.home`。当前已接入 Hosting 的 Scene 级内容租约，因此 Home→WorldMap 会释放 Home Atlas，WorldMap→Home 会重新加载 Home。WorldMap 在正式资产清单建立前仍是 package-free 占位场景。

## 渐进实施顺序

1. **坐标与相机样本**：先固定 Room、View、五段起始坐标和滚动边界，使用无窗口测试验证拖动与回弹。
2. **第一岛屿段景观**：只迁移底部 1–20 关段的两张岛屿图、必要云层和少量装饰，建立 `WorldMap/assets.json`。
3. **关卡节点展示**：由不可变进度快照生成三种节点状态；点击只发布选择事件。
4. **五段虚拟化**：按相机可见范围激活段与装饰，避免 100 个节点和所有粒子永久更新。
5. **景观过渡**：加入岛屿漂移、云层视差和天空颜色混合。
6. **产品层后置**：核心关卡与存档契约稳定后，再讨论关卡开始面板和资源栏。

## 非目标与审计 Gate

- 本文不授权复制旧 GML、SDK、第三方 UI 或商业化逻辑。
- 旧图片即使转成 WebP，许可状态也不会改变；进入公开构建前必须逐项完成来源与再分发权限审计。
- 不要求一次渲染完整 16100px 世界，也不创建超大单纹理。
- 不为 100 个关卡创建 100 个 Scene；它们仍是一个 WorldMap 上的数据节点。
