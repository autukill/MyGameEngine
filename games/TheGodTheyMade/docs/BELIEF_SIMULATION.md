# 信仰推演系统

## 设计目标

信仰系统要制造“合理的误解”，而不是随机笑话。玩家必须能够追溯一条信仰为何形成，并能通过行动强化、反证或重新解释它。

第一版不生成自由文本概念，只组合经过策划的事实、原因、结果与行为规则。

## 可观察事件

首岛只开放一小组稳定词汇：

```text
BellRang
RainStarted
RainEnded
CropWithered
CropRecovered
FireStarted
FireExtinguished
OfferingPlaced
FuneralStarted
FamiliarArrived
FamiliarActed
VillagerInjured
VillagerRecovered
```

每个事件至少包含：发生 Tick、种类、主体、世界位置、显著性和可见范围。事件只有被村民实际观察到，才进入其记忆；全知系统不能偷偷替村民补全真相。

## 从观察到假说

当一个重要结果发生时，观察者回看有限时间窗内的候选原因：

```text
证据强度 = 显著性 × 时间接近度 × 空间接近度 × 观察可靠度
```

第一版规则：

- 因果回看窗口最多 8 秒。
- 越接近结果发生时刻，证据越强。
- 同一地点的事件优先于远处事件。
- 没看见的事件不能成为个人信仰证据。
- 每名村民只保留有限数量的活跃假说，避免组合爆炸。
- 相同条件发生但结果没有出现时，形成反证。
- 信心变化是渐进的，不因一次巧合直接变成绝对教义。

概念数据结构：

```csharp
BeliefHypothesis(
    BeliefCause Cause,
    BeliefEffect Effect,
    float Confidence,
    int SupportingEvidence,
    int Contradictions);
```

## 个人信仰与公共教义

系统最终分为两层，但首个灰盒可以渐进实现：

1. **个人假说**：由亲眼所见形成，影响个人行为。
2. **公共教义**：在集会、工作或家庭交流中传播，影响仪式和村庄任务。

首版传播不是句子模拟。拥有高确信度、较高社会影响力的村民在聚集时，把一条假说作为证言传递；听者降低权重后接收。不同村民可以暂时持有矛盾信仰。

## 信仰必须改变行为

每条可进入公共教义的信仰必须绑定至少一个可见行为，否则不允许加入首版内容：

| 信仰 | 可能行为 |
|---|---|
| 钟声召来雨 | 干旱时优先敲钟，并维护钟塔。 |
| 烟雾取悦神 | 缺水时焚烧供品，产生新的火灾风险。 |
| 神兽保护麦田 | 村民允许神兽进入农田，并模仿它的动作。 |
| 雨会带走亡魂 | 葬礼期间遮盖遗体或反对降雨。 |

## 玩家如何纠正误解

玩家没有“删除信仰”按钮，只能改变证据：

- **反证**：钟声响起时不降雨。
- **对照**：没有钟声时主动降雨。
- **替代解释**：稳定地在另一项可见条件之后降雨。
- **承认误解**：持续配合仪式，使其成为可靠规则，即使最初只是巧合。

纠正必须允许失败。如果错误教义已经深度嵌入工作和社会地位，单次反证只能造成怀疑，不能立即抹除共同记忆。

## 可解释性界面

玩家查看信仰时看到的是证据链，而不是内部公式：

```text
钟声召来雨？  可信度：较高

支持：
- 钟响后不久下雨，麦田得救。
- 葬礼钟响后也出现了雨。

怀疑：
- 昨日钟响了三次，但没有下雨。
```

这些信息可使用 MyGameEngine 现有文本与 SceneGui 绘制。首版不依赖完整 GUI 框架。

## 确定性与测试

- 相同事件序列必须产生相同假说变化。
- 随机数只用于置信度相同情况下的稳定破局，并使用 GameplayRandom。
- 信仰更新由事件触发，不每帧扫描全世界。
- 单元测试覆盖时间窗边界、不可见事件、支持、反证、传播和容量淘汰。
- 固定场景测试应能定位首次信仰分叉 Tick，并纳入 Gameplay State Hash。

## 明确不做

- 不使用 LLM 生成教义或村民对话。
- 不允许任意自然语言成为因果节点。
- 不模拟完整心理学、政治学或宗教史。
- 不让所有事件两两组合；只有策划注册的因果类别可以形成假说。
